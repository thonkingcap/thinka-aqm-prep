# Security

Thinka's AQM Prep asks students for a Claude API key (usually the one Babson emails them). This is how that key is protected, so anyone can check it against the code.

## Where the key goes

- **Nowhere but the AI service.** There's no Thinka server. The page sends the key only to Babson's Claude gateway (or `api.anthropic.com` for keys made at platform.claude.com).
- **Enforced by the browser.** The Content-Security-Policy (`vite.config.ts`, `vercel.json`) lets the page connect only to those two services and to formsubmit.co, which handles the "Have a problem?" form and never receives the key. Any other destination is blocked by the browser itself.
- **Never in other text.** The feedback form and the tutor chat both refuse to send a message that contains a key.

## How it's stored (`src/lib/vault.ts`)

- **Encrypted, never in plain text.** The key is encrypted with AES-256-GCM. The encryption key is generated by the browser as non-extractable and kept in IndexedDB: the page can ask the browser to decrypt with it, but nothing can read its bytes, so a copied browser profile or a localStorage dump is useless on another machine.
- **Shared computer option.** The encrypted key is kept in the tab only, and closing the tab forgets it.
- **Forgotten when unused.** A remembered key is deleted after 14 days without a visit.
- **"Remove key" deletes everything,** both the encrypted key and the encryption key.

## Other browser protections

These are set in `vercel.json` and `public/_headers`:

- **Scripts:** only the site's own scripts can run. Inline and third-party scripts are blocked, and there are no source maps.
- **Trusted Types:** the browser refuses to turn strings into HTML or script, which closes off most cross-site scripting.
- **No framing:** the site can't be embedded in another page, which blocks clickjacking (`frame-ancestors 'none'`, `X-Frame-Options`).
- **Isolation:** another window can't reach into this one (`Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy`).
- **No referrer:** links and requests don't tell other sites which page they came from.
- **HTTPS only (HSTS).**

## Limits

A web page can't protect a key from malware or a malicious browser extension on the same computer, because those can act as the page itself. Use a device you trust. If you think your key leaked, ask Babson for a new one.

## Reporting a problem

Please report security issues privately through GitHub's **"Report a vulnerability"** button on this repository (Security tab), or through the site's "Have a problem?" form. Please don't open a public issue for them.

## Offline mode

The site registers a service worker (`/sw.js`, generated at build time from `src/sw-template.js`) that saves the site's own files on the device so it works without internet. It only handles same-origin GET requests for those files: it never sees or stores your API key or any request to Claude, Babson's gateway or the feedback form. The Content-Security-Policy allows `worker-src 'self'` and `connect-src 'self'` for this, and Trusted Types allows a single policy, `sw`, that accepts exactly the URL `/sw.js`; any other script URL still throws.

## Usage logs

So the author can see how many students the site helps, it logs a little usage to a Supabase database (project `aqm-prep-logs`):

- the name you type on your first visit, and a random visitor id kept in your browser;
- active minutes on the site (only while the tab is visible and you've used it in the last 10 minutes), sent every 5 minutes and when you leave;
- one row per request sent to Claude, labelled only with the feature (tutor, marking, custom set, plan, key check), and a row when you add a key;
- each Claude reply's estimated cost and token counts;
- a key tag: the first 10 characters of a one-way SHA-256 fingerprint of your key (or "code" for an access code), so the author can count unique keys. It can't be turned back into the key.

It never logs your API key itself, your answers or your messages. Your key still goes only to Claude (Babson's gateway or Anthropic). The site calls a single database function, `log_event`, that can only append a validated row; the public key in the code can't read, change or delete anything. The author reads the stats on a hidden page through `admin_stats`, which only answers to the right admin code: the database stores only a bcrypt hash of it, and wrong codes lock it for 10 minutes after 20 tries. The CSP adds `https://kxtdmgpecxlzyepshryw.supabase.co` to `connect-src` for this. Logging is skipped while you're offline.

## Access codes

Some students don't have a Babson Claude key. Daniel can give them an access code instead. The code is
typed where a key would go, stored like a key (as `aqmcode:<CODE>`), and sent only to this site's own
function at `/api/claude` (`api/claude.ts`, logic in `api/_proxy.ts`). That function:

- accepts only `GET /v1/models` and `POST /v1/messages`, from this site's origin (or localhost);
- checks the code against `ACCESS_CODES` (comma-separated, case-insensitive) in Vercel's environment;
- forwards the request with Daniel's key from `OWNER_API_KEY` in Vercel's environment. The key never
  reaches a browser, the repository or any response, and the student's code is not forwarded;
- allows Claude models only, caps `max_tokens` at 16,000 and request bodies at 4 MB, and limits each
  IP address to 60 requests per 10 minutes (per server instance);
- never caches anything (the offline service worker skips `/api/`).

To revoke a code, remove it from `ACCESS_CODES` in Vercel and redeploy. Removing `OWNER_API_KEY` or
`ACCESS_CODES` switches shared access off entirely.
