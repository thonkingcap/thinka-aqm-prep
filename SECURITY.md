# Security

Thinka's AQM Prep asks students for a Claude API key (usually the one Babson emails them). This is how that key is protected, so anyone can check it against the code.

## Where the key goes

- **Nowhere but the AI service.** There's no Thinka server. The page sends the key only to Babson's Claude gateway (or `api.anthropic.com` for keys made at platform.claude.com).
- **Enforced by the browser.** The Content-Security-Policy (`vite.config.ts`, `vercel.json`) lets the page connect only to those two services and to formsubmit.co, which handles the "Have a problem?" form and never receives the key. Any other destination is blocked by the browser itself.
- **Never in other text.** The feedback form and the tutor chat both refuse to send a message that contains a key.

## How it's stored (`src/lib/vault.ts`)

- **Encrypted, never in plain text.** The key is encrypted with AES-256-GCM. The encryption key is generated by the browser as non-extractable and kept in IndexedDB: the page can ask the browser to decrypt with it, but nothing can read its bytes, so a copied browser profile or a localStorage dump is useless on another machine.
- **Shared computer option.** The encrypted key is kept in the tab only, and closing the tab forgets it.
- **Forgotten when unused.** A remembered key is deleted after 14 days without a visit.
- **"Remove key" deletes everything,** both the encrypted key and the encryption key.

## Other browser protections

These are set in `vercel.json` and `public/_headers`:

- **Scripts:** only the site's own scripts can run. Inline and third-party scripts are blocked, and there are no source maps.
- **Trusted Types:** the browser refuses to turn strings into HTML or script, which closes off most cross-site scripting.
- **No framing:** the site can't be embedded in another page, which blocks clickjacking (`frame-ancestors 'none'`, `X-Frame-Options`).
- **Isolation:** another window can't reach into this one (`Cross-Origin-Opener-Policy` and `Cross-Origin-Resource-Policy`).
- **No referrer:** links and requests don't tell other sites which page they came from.
- **HTTPS only (HSTS).**

## Limits

A web page can't protect a key from malware or a malicious browser extension on the same computer, because those can act as the page itself. Use a device you trust. If you think your key leaked, ask Babson for a new one.

## Reporting a problem

Please report security issues privately through GitHub's **"Report a vulnerability"** button on this repository (Security tab), or through the site's "Have a problem?" form. Please don't open a public issue for them.
